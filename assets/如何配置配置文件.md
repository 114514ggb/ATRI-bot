## 配置热更新（WebUI 保存即生效的部分）

WebUI 保存 `config.json` 时会对比出发生变化的顶层配置段，重载后通知订阅了该段的服务，无需重启：

| 配置段 | 生效内容 |
|---|---|
| `tool_presets` | LLM 工具预设（含 `deferred` 待发现组） |
| `initiative_chat_keyword_trigger` | 主动聊天关键词表 |
| `model` | 群聊/私聊模型（`connect`、`group_chat`、`private_chat`）、`chat_parameter`、`standby_model` |
| `group_white_list` / `root_user_id` | 群白名单与 root 用户 |
| `private_chat_white_list` | LLM 私聊白名单 |
| `network` | 网络出口的 DNS / 代理（仅 `HTTPClient` 立即重建连接池，其余长连接需重启） |

实现方式：服务在初始化时把需要的配置取一次缓存起来，并通过 `atriConfig.on_change(section, callback)` 订阅变更；WebUI 保存/回滚后调用 `reload_section()` 自动触发回调。
其余配置段（`platforms`、`database`、`web_panel`、`sand_box`、`tts`、`ai_chat` 等）以及 `supplier_config.json` 的改动仍需重启 bot 生效。

## config.json

### platforms（平台连接）

支持的适配器（`adapter`）：`onebot`（NapCat 等 OneBot v11 实现）、`snowluma`（SnowLuma，OneBot v11）、`qqbot`（QQ 官方机器人 API v2）。
`connection_type` 决定使用哪种连接方式，共四种模式：

| connection_type | 说明 | 特有字段 |
|---|---|---|
| `WebSocket_client` | bot 主动连接协议端的 WS 服务端 | `url`（连接地址）、`ws_path`（可选） |
| `WebSocket_server` | bot 作为 WS 服务端，等协议端来连 | `host`（监听地址）、`port`（监听端口） |
| `http` | 协议端把事件 POST 给 bot，bot 通过 HTTP API 发送 | `url`（协议端 API 地址，需含 `http://`）、`host`、`port`（bot 监听地址） |
| `qqbot` | 直连 QQ 官方机器人 WebSocket 网关（不需要 NapCat） | `app_id`、`app_secret`（可选 `sandbox`） |

```json
"platforms": {
    "napcat": {
        "adapter": "onebot",
        "connection_type": "WebSocket_client",
        "access_token": "ATRI114514",
        "url": "127.0.0.1:8888"
    },
    "qqbot": {
        "adapter": "qqbot",
        "connection_type": "qqbot",
        "app_id": "你的 AppID",
        "app_secret": "你的 AppSecret",
        "sandbox": false,
        "enabled": false
    }
}
```

| 字段 | 说明 |
|---|---|
| `adapter` | 适配器类型：`onebot` / `snowluma` / `qqbot` |
| `access_token` | 访问令牌，需与协议端配置一致（`WebSocket_client` / `WebSocket_server` / `http`） |
| `enabled` | 可选，默认 `true`，是否启用该平台实例 |
| `source_name` | 可选，来源标识，留空则取平台条目的 key |
| `ws_path` | 可选，仅 `WebSocket_client`：WS 连接路径，不填时沿用 `/websocket` |
| `app_id` | 必填，仅 `qqbot`：QQ 开放平台机器人 AppID |
| `app_secret` | 必填，仅 `qqbot`：QQ 开放平台机器人 AppSecret（敏感信息，面板保存后回显为占位符） |
| `sandbox` | 可选，仅 `qqbot`：`true` 时使用沙箱环境 `sandbox.api.sgroup.qq.com` |
| `text_chunk_size` | 可选，仅 `qqbot`：单条文本最大字符数（默认 1500），超出自动分片 |
| `max_passive_replies` | 可选，仅 `qqbot`：同一条入站消息最多被动回复次数（默认 5，官方上限） |
| `allow_proactive` | 可选，仅 `qqbot`：无被动回复目标时是否允许主动消息（受官方配额限制，默认 `false`） |
| `id_map` | 可选，仅 `qqbot`：openid → 整数 ID 的手工映射，形如 `{"group": {"<openid>": 123}, "user": {...}}`；需直接编辑文件 |

> 平台的 key（如 `napcat`）可以随意命名，同时可配置多个平台实例，`enabled: false` 的不会启动。完整配置示例见 `config copy.json`。

不建议使用官方的bot谢谢,很多功能都不能正常使用
> **QQ 官方机器人的限制**：群聊只能收到 **@ 机器人** 的消息；`group_openid` / `user_openid` 会映射成整数 ID（重启不变，日志会打印映射），白名单可直接写 openid 字符串；被动回复有 5 分钟窗口与次数上限，主动消息受官方配额限制；禁言 / 戳一戳 / 贴表情 / 群成员查询 / 合并转发等能力不可用（自动降级或忽略）。开通步骤与排障见 [atribot/docs/qqbot-adapter.md](../atribot/docs/qqbot-adapter.md)。

### root_user_id（账号权限）

```json
"root_user_id": 2631018780
```

| 字段 | 说明 |
|---|---|
| `root_user_id` | root 用户的 QQ 号，有执行命令的最高权限。不管在哪个群都会无视其他配置名单，强制接受这个 QQ 号的消息 |

> bot 自己的 QQ 号与昵称不再需要配置：平台连接建立后会自动调用 `get_login_info` 获取一次（只获取一次，换号或改昵称需重启 bot）。启动时最多等待约 10 秒（统一上限，不提供配置项）；即使连接失败或超时也不会阻断启动，Web 管理面板与命令仍可用，只是提示词中会缺少 bot 的 QQ 号。

### network（网络配置）

全局 HTTP 出口的 DNS 与代理设置，整段可以不写（默认使用系统 DNS）。

国内网络 / VPN / 多网卡 / WSL 环境下，`aiohttp` 默认的 c-ares 解析器可能读不到可用的 nameserver，日志会刷 `Could not contact DNS servers`，表现为 QQ 官方机器人反复重连但永远连不上。此时保持 `dns_mode=system`（默认）或在 `custom` 里写明 DNS 服务器即可。

```json
"network": {
    "dns_mode": "system",
    "dns_nameservers": [],
    "proxy": "",
    "proxy_bypass": ["bots.qq.com", "api.sgroup.qq.com", "sandbox.api.sgroup.qq.com", "localhost", "127.0.0.1", "::1"],
    "trust_env": false,
    "connect_timeout": 10,
    "total_timeout": 30,
    "probe_hosts": ["bots.qq.com", "api.sgroup.qq.com"]
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `dns_mode` | `system` | `system` 用系统 DNS（getaddrinfo，兼容性最好）；`custom` 用 `dns_nameservers` 指定的 DNS；`cares` 沿用 aiohttp 默认（装了 aiodns 时即 c-ares） |
| `dns_nameservers` | `[]` | `dns_mode=custom` 时必填，如 `["223.5.5.5", "119.29.29.29"]` |
| `proxy` | `""` | HTTP(S) 代理地址，如 `http://127.0.0.1:7890`；留空表示直连 |
| `proxy_bypass` | QQ 官方域名 + 本机 | 不走代理的主机，按完全相等或域名后缀匹配 |
| `trust_env` | `false` | 是否让 aiohttp 读取环境变量里的代理配置（`HTTP_PROXY` 等） |
| `connect_timeout` / `total_timeout` | `10` / `30` | 建连超时 / 单次请求整体超时（秒） |
| `probe_hosts` | `bots.qq.com`、`api.sgroup.qq.com` | 启动时 DNS 自检探测的主机 |

- 启动时会做一次 DNS 自检（日志前缀 `atri-bot.Network`）：配置的解析方式失败会自动尝试降级为系统 DNS；仍失败只告警、不阻断启动，并打印可用配置建议
- 生效范围：QQ 官方机器人网关 / Token、OneBot HTTP 模式、`HTTPClient`、LLM API 客户端统一走这套设置
- 修改后仅 `HTTPClient` 立即重建连接池（WebUI 保存即生效），其余长连接需重启 bot
- Docker 部署也可用环境变量覆盖：`ATRI_NETWORK_DNS_MODE`、`ATRI_NETWORK_DNS_NAMESERVERS`（逗号分隔）、`ATRI_NETWORK_PROXY`、`ATRI_NETWORK_TRUST_ENV`

### file_path（路径配置）

没事的话可以不配置，使用默认的即可。如果没有对应目录会自动创建。

```json
"file_path": {
    "resolve_paths": false,
    "create_dirs": false,
    "document_root": null,
    "emoji": null,
    "relative_to_root": {
        "commands": "atribot/commands",
        "chat_manager": "atribot/LLMchat/character_setting",
        "supplier_config_path": "assets/supplier_config.json",
        "tool_calls": "atribot/LLMchat/tools",
        "mcp_config": "atribot/LLMchat/MCP/mcp_server.json",
        "agent_skills": "atribot/LLMchat/skills/agent_skills",
        "plugins": "atribot/plugins"
    },
    "relative_to_document": {
        "audio": "audio",
        "file": "file",
        "img": "img",
        "video": "video",
        "temp": "temp"
    },
    "path_mapping": {}
}
```

| 字段 | 说明 |
|---|---|
| `resolve_paths` | 是否强制将相对路径转为绝对路径 |
| `create_dirs` | 是否创建目录，确保目录存在 |
| `document_root` | 项目资源根目录（表情包、音频等目录的位置）。为空则默认在项目根目录下的 `document` 文件夹，可以换位置但不建议 |
| `emoji` | 表情目录的绝对路径。为空则默认是 `项目根目录/document/img/emojis` |
| `relative_to_root` | 相对项目根目录（`main.py` 所在位置，会自动获取）的路径映射，见下表 |
| `relative_to_document` | 相对 `document_root` 的目录映射，见下表 |
| `path_mapping` | 本地路径前缀 → 协议端（NapCat 等）路径前缀的映射，bot 和协议端不在同一文件系统时用于转换发送的 `file://` 路径。为空时不做任何转换 |

`path_mapping` 示例（NapCat 运行在 WSL 中，Windows 的 `E:` 盘在 WSL 里挂载为 `/mnt/e`）：

```json
"path_mapping": {
    "E:/程序文件/python/ATRI-main": "/mnt/e/程序文件/python/ATRI-main"
}
```

发送图片/语音/文件时，消息里 `file://E:/程序文件/python/ATRI-main/...` 会被自动替换成 `file:///mnt/e/程序文件/python/ATRI-main/...`，匹配不区分大小写、支持多条映射（最长前缀优先）。

`relative_to_root` 各项：

| key | 说明 |
|---|---|
| `commands` | 加载提供系统使用命令的目录 |
| `chat_manager` | 角色设定所在的目录 |
| `supplier_config_path` | 供应商配置文件路径 |
| `tool_calls` | 供 ai 调用工具实现文件夹 |
| `mcp_config` | MCP 配置文件路径 |
| `agent_skills` | 读取 skills 的目录 |
| `plugins` | 插件目录 |

`relative_to_document` 各项：`audio`（音频）、`file`（文件）、`img`（图片）、`video`（视频）、`temp`（临时目录）、`work`（沙盒本地工作区，本机直执行后端默认使用）。

### model（模型配置）

#### connect（主聊天模型）

```json
"connect": {
    "supplier": "zaxprisのapi",
    "model_name": "Nvidia/deepseek-ai/deepseek-v4-flash",
    "user_global_context": true
}
```

| 字段 | 说明 |
|---|---|
| `supplier` | 聊天模型来自的供应商（对应 supplier_config.json 中 `api[].name`） |
| `model_name` | 聊天模型名称（对应 supplier_config.json 中 `models` 的 key） |
| `user_global_context` | 上下文模式：`true` = 群聊每个人独立上下文（使用自己的私聊上下文）；`false` = 每个群的人共享一个群聊上下文 |

#### group_chat / private_chat（群聊 / 私聊模型覆盖）

两块均为可选：群聊、私聊可以各用一套模型，缺省或留空时回退上面的 `connect` 主模型。

```json
"group_chat": {
    "supplier": "zaxprisのapi",
    "model_name": "Nvidia/deepseek-ai/deepseek-v4-flash"
},
"private_chat": {
    "supplier": "bigModel",
    "model_name": "GLM-4.6V-Flash"
}
```

| 字段 | 说明 |
|---|---|
| `supplier` | 该场景使用的供应商（对应 supplier_config.json 中 `api[].name`） |
| `model_name` | 该场景使用的模型（对应 supplier_config.json 中 `models` 的 key） |

> 保存后立即热生效（含 `connect` 主模型、`chat_parameter`、`standby_model`）。若填写的供应商/模型尚未在运行中加载（`supplier_config.json` 的改动需要重启），只记录告警并继续使用原来的模型，不会让聊天中断。

#### chat_parameter（聊天模型参数）

```json
"chat_parameter": {
    "thinking_level": "high",
    "temperature": 0.3,
    "max_tokens": 8000,
    "response_format": { "type": "json_object" },
    "stream": false,
    "tool_choice": "auto"
}
```

| 字段 | 说明 |
|---|---|
| `thinking_level` | 思考等级：`minimal` / `low` / `medium` / `high` |
| `temperature` | 采样温度 |
| `max_tokens` | 最大生成 token 数 |
| `response_format` | 挺支持用 `{"type": "json_object"}` 这个参数的，效果还行，一般不会出现无法解析的格式 |
| `stream` | 是否流式 |
| `tool_choice` | 工具选择模式 |

`chat_parameter` 是自由字典：不限于上表字段，任意额外键值对都会原样随请求发送给模型 API（OpenAI 兼容格式）。上表为空/整个 `chat_parameter` 缺省时使用内置默认参数。WebUI 的「聊天请求参数」区块同样支持自由增删键值对。

#### 其他模型配置

| 字段 | 说明 |
|---|---|
| `tavily_search_API_key` | 网络搜索的 api，挺好用的（免费）：https://docs.tavily.com/ |
| `detection_image` | 用于视觉辅助，给没有视觉的模型提供文字描述使用的模型 |
| `detection_audio` | 给没有输入音频能力的模型提供文字描述使用的模型 |
| `detection_video` | 给没有输入视频能力的模型提供文字描述使用的模型 |
| `memory.summarize_model` | 总结群聊天内容做为模型记忆的模型 |
| `agency_Agent` | 给 ai 子代理使用的模型 |

#### standby_model（备用模型）

当主聊天模型尝试失败后，会按列表顺序使用其他供应商或其他模型。备用模型使用的模型参数是一个默认的通用参数（硬编码在程序里）。

```json
"standby_model": [
    { "supplier": "星见雅api", "model_name": "z-ai/glm-5.1" },
    { "supplier": "zaxprisのapi", "model_name": "Nvidia/deepseek-ai/deepseek-v4-pro" },
    { "supplier": "bigModel", "model_name": "GLM-4.6V-Flash" }
]
```

#### RAG（记忆检索）

对模型提供记忆搜索支持的嵌入式模型。

```json
"RAG": {
    "enable": true,
    "dimensions": 1024,
    "use_embedding_model": {
        "supplier": "ollama_embed",
        "model_name": "dengcao/Qwen3-Embedding-0.6B:F16"
    },
    "use_reranker_model": {
        "supplier": "ollama_embed",
        "model_name": "dengcao/Qwen3-Reranker-8B:Q4_K_M"
    },
    "vector_database": {}
}
```

| 字段 | 说明 |
|---|---|
| `enable` | 目前没什么用，修改不影响，整个项目需要依赖这个 |
| `dimensions` | 嵌入模型的向量维度 |
| `use_embedding_model` | 嵌入模型，一般配置这个就行了 |
| `use_reranker_model` | 重排序模型（目前没用） |
| `vector_database` | 向量数据库配置 |

### ai_chat（聊天参数）

```json
"ai_chat": {
    "playRole": "ATRI_simplify",
    "ai_max_record": 10,
    "group_max_record": 20,
    "private_max_record": 20
}
```

| 字段 | 说明 |
|---|---|
| `playRole` | 聊天采用的人设名，要是 `chat_manager`（角色设定目录）里面有的人物，不然就是没有人设 |
| `ai_max_record` | 上下文的消息存储的消息轮数 |
| `group_max_record` | 群消息缓存的消息条数量（作为 ai 上下文） |
| `private_max_record` | user 上下文消息轮数限制 |

> 注意：消息轮数是指你输入一条消息然后等到 ai 回复一次这就是一轮，这一轮里面可能包含 ai 多次工具调用。

### sand_box（沙盒）

沙盒的配置参数，需要看具体使用的沙盒实例来传递。

`type` 支持三种后端：

| type | 说明 | 专属参数 |
|---|---|---|
| `docker`（默认） | Docker 容器沙盒，见 `atribot/LLMchat/sandbox/docker_sandbox.py` | `image` |
| `none` | 「没有沙盒」，直接在本机执行命令和代码（无隔离，注意安全），支持 Linux/Windows。见 `atribot/LLMchat/sandbox/no_sandbox.py` | `work_dir`（默认 `document/work`）、`shell`（默认自动：Linux 用 `/bin/sh`；Windows 优先找 Git Bash，找不到退回 cmd） |
| `e2b` | E2B 云端沙盒，见 `atribot/LLMchat/sandbox/E2B_sandbox.py` | `api_key`、`template` |

与沙盒相关的工具（`run_python_code` / `run_command` / `send_file` / `add_file`）的描述会按当前后端、平台与 shell 自动生成：

- `tool_prompts`：给某个工具追加或替换描述。值为字符串时追加到内置环境描述之后；值为 `{"description": "...", "append": "..."}` 时整体替换 / 追加。
- `tools`：单独启停某个沙盒工具（默认全部启用；沙盒不可用时全部自动禁用，模型看不到）。

运行中可让配置立即生效（无需重启进程）：

- 聊天命令 `/tools reload`（需管理员权限），或
- WebUI `POST /api/sandbox/refresh-tools`（会按当前 `sand_box` 配置重建沙盒并全量重载工具描述/启用状态）。

```json
"sand_box": {
    "type": "docker",
    "image": "atri-sandbox:latest",
    "tool_prompts": {
        "run_command": "本项目用 uv 管理依赖，执行 python 请写 uv run python"
    },
    "tools": {}
}
```

### tool_presets（工具预设）

各个聊天模块所使用的工具列表，每一项对应 `LLMchat/tools/` 下的一个工具目录名。`group_chat` / `private_chat` / `agency_Agent` 三个模块都支持以下三种取值：

1. **列表（白名单）**：只有列表内的工具会直接暴露给模型；列表为空代表该模块没有任何可用工具。
2. **字典**：`{"default": [...], "deferred": [...]}` 拆分为「默认启用」与「待发现」两组（如 `group_chat`）。
3. **`null`**：不限制，该模块直接使用全部已加载的工具（不推荐，很多工具是群聊/管理专有的，全部暴露有风险）。

注意：**省略某个模块的键 ≠ `null`**。省略后该模块不会被注册，等于没有任何可用工具（日志中会有警告）。想用全部工具必须显式写 `"private_chat": null`。

```json
"tool_presets": {
    "group_chat": {
        "default": [
            "web_search", "web_extract",
            "memory_search", "memory_storage",
            "load_skill_prompt", "get_user_info",
            "tool_search"
        ],
        "deferred": [
            "run_python_code",
            "run_command",
            "send_file", "add_file",
            "send_image_message",
            "schedule_self_trigger", "sub_agent"
        ]
    },
    "private_chat": {
        "default": [
            "web_search", "memory_search",
            "load_skill_prompt", "get_user_info",
            "tool_search"
        ],
        "deferred": [
            "run_python_code",
            "send_file", "add_file",
            "send_image_message", "send_speech_message",
            "schedule_self_trigger"
        ]
    },
    "agency_Agent": [
        "run_command",
        "send_file", "add_file",
        "get_user_info", "memory_search",
        "web_search", "web_extract"
    ]
}
```

| 字段 | 说明 |
|---|---|
| `default` | 默认直接暴露，模型可直接调用 |
| `deferred` | 待发现工具，不会直接暴露；模型可通过 `tool_search` 搜索后在本轮临时启用（仅本轮有效） |

`tool_search` 与 `deferred` 必须成对出现，缺一个都没有意义（WebUI 保存时会校验并拦截）：
- 配置了 `deferred` 就必须把 `tool_search` 加进 `default`，不然 deferred 里的工具无法被发现；
- `default` 里有 `tool_search` 就必须在 `deferred` 中至少放一个工具，不然没有可发现的内容。

补充：子代理 `agency_Agent` 若写成字典格式，只取 `default` 部分（子代理没有 `tool_search` 发现机制）；WebUI 中在私聊/子代理的白名单里输入 `tool_search` 回车，会自动切换为「默认 + 待发现」双列表编辑模式，「限制工具」开关关闭即保存为 `null`。

### 名单配置（白名单）

```json
"group_white_list": [ 2169027872 ],
"group_initiative_chat_white_list": [],
"group_information_extraction": [],
"private_chat_white_list": [ 114514 ],
"initiative_chat_keyword_trigger": [ "哈基莉", "atri-bot", "ATRI-bot" ]
```

| 字段 | 说明 |
|---|---|
| `group_white_list` | 有效的群白名单，只有在名单内的群会接收消息处理 |
| `group_initiative_chat_white_list` | 默认的启动主动聊天的名单。首先这个名单出现过的群要也在 `group_white_list` 出现过，才有效 |
| `group_information_extraction` | 默认的启动群消息提取，会由 `summarize_model` 配置的模型进行提取然后存入数据库 |
| `private_chat_white_list` | 允许触发 LLM 私聊的用户 QQ 号白名单。不在名单内的用户私聊不进 LLM（命令和消息记录不受影响），`root_user_id` 可绕过 |
| `initiative_chat_keyword_trigger` | 主动聊天的关键词触发列表：群里出现这些词（子串匹配、**大小写不敏感**）且 Bot 近期发言不多时，会更倾向主动接话 |

`initiative_chat_keyword_trigger` 的取值语义：

- **不写这一项**（或写成 `null`）：使用内置默认 `哈基莉` / `atri-bot` / `ATRI-bot`；
- **显式写空数组 `[]`**：关闭关键词触发（其余主动聊天逻辑不受影响）；
- 元素前后空白会被去掉，非字符串/空字符串元素会被忽略；整项不是数组时按「未配置」处理并打 warning。

以上名单与关键词都可以在 WebUI 配置页的「白名单」分组里直接编辑（关键词是回车添加的标签式列表）。保存后 `group_white_list` / `root_user_id` / `private_chat_white_list` / `initiative_chat_keyword_trigger` **立即生效**；`group_initiative_chat_white_list` 与 `group_information_extraction` 仍在启动时读取，改动需重启 bot。

### web_panel（Web 管理面板）

可选配置，控制 bot 自带的 Web 管理面板。整个节点不写的话默认启用、监听 `127.0.0.1:5125`。启动后浏览器访问 `http://127.0.0.1:端口/admin/`。

```json
"web_panel": {
    "enable": true,
    "host": "127.0.0.1",
    "port": 5125,
    "access_token": "ATRI",
    "session_ttl_hours": 4
}
```

| 字段 | 说明 |
|---|---|
| `enable` | 是否启动管理面板，默认 `true`；设为 `false` 可完全关闭面板 |
| `host` | 面板监听的地址，默认 `127.0.0.1`（只绑本机）。容器部署需要写 `0.0.0.0` 才能从宿主机访问，也可用环境变量 `ATRI_WEB_PANEL_HOST` 覆盖 |
| `port` | 面板监听的端口，默认 `5125`；也可用环境变量 `ATRI_WEB_PANEL_PORT` 覆盖（Docker 部署用它对齐端口映射） |
| `access_token` | 面板主令牌/登录口令，建议 32 字符以上随机值；留空时读取环境变量 `ATRI_PANEL_TOKEN`（优先级：本字段 > 环境变量；均未配置时面板接口全部返回 503） |
| `session_ttl_hours` | 登录会话的固定有效期（小时，1-24），默认 `4`；到期后 WebUI 自动退出登录 |

> 修改本节点后需要重启 bot 才会生效；面板里改配置保存时同样会提示重启。

### tts（语音合成，可选）

控制 GPT-SoVITS 语音合成。**不配置本节点也可以启动**：此时使用内置默认情感（`高兴` / `机械` / `平静`），参考音频按 `document/audio/tts_reference/` 下的同名 mp3 解析（找不到时只记录 warning，不影响启动）。

> 本节点也可在 Web 管理面板的「配置 → 语音合成」区块图形化编辑（情感列表可增删改，保存后需重启 bot 生效）。

```json
"tts": {
    "api_url": "http://127.0.0.1:9880",
    "emotions": {
        "平静": {
            "refer_wav_path": "D:/tts_reference/夏生さんが望むのでしたら.mp3",
            "prompt_text": "夏生さんが望むのでしたら",
            "prompt_language": "ja"
        }
    }
}
```

| 字段 | 说明 |
|---|---|
| `api_url` | GPT-SoVITS 接口地址，默认 `http://127.0.0.1:9880` |
| `emotions` | 情感名 → 参考音频配置。键名可由你自定义，命令 `/tts --emotion <名>` 与工具 `send_speech_message` 的 `emotion` 取值即来源于此；**未配置时**回退内置三情感 |
| `emotions.<名>.refer_wav_path` | 参考音频路径。相对路径相对于本配置文件所在目录解析，**跨平台建议直接写绝对路径**（Windows 用正斜杠或双反斜杠）。注意：该路径是给 GPT-SoVITS 服务读取的，若 TTS 与 bot 不在同一文件系统（例如 bot 在容器里），需要填 TTS 侧可见的路径 |
| `emotions.<名>.prompt_text` | 参考音频对应的文本 |
| `emotions.<名>.prompt_language` | 参考文本语言，如 `ja` / `zh` / `auto` |

> 旧版本曾硬编码 `/home/atri/音乐/tts_reference/...`，现已移除；请按上面的方式在 `config.tts.emotions` 中配置，或把参考音频放到 `document/audio/tts_reference/` 下。

## supplier_config.json

`api` 是一个数组，每个元素是一个供应商。`supplier` / `model_name` 填写时与这里的 `name` / `models` 的 key 对应。

```json
{
    "api": [
        {
            "name": "deepseek",
            "base_url": "https://api.deepseek.com/chat/completions",
            "api_key": "sk-????",
            "models": {
                "deepseek-chat": {
                    "visual_sense": false,
                    "audio_sense": false,
                    "video_sense": false,
                    "document_sense": false
                },
                "deepseek-reasoner": {}
            }
        }
    ]
}
```

| 字段 | 说明 |
|---|---|
| `name` | 供应商名称，作为 config.json 中 `supplier` 的参考值 |
| `base_url` | 只接受 openai 兼容的地址。一般要在地址后面加上 `v1/chat/completions`，比如谷歌的 openai 兼容地址是 `https://generativelanguage.googleapis.com/v1beta/openai`，要加后缀变成 `https://generativelanguage.googleapis.com/v1beta/openai/v1/chat/completions`。对于嵌入模型一般就不需要了，比如 `https://api.siliconflow.cn/v1/embeddings`。如果 api 文档里有写，就使用 curl 里面的 url 地址 |
| `api_key` | 你的密钥。可以是一个 list 类型，那样就可以输入多个密钥成为一个号池，请求时会按照顺序轮流使用里面的 key |
| `models` | 模型名称（对应上面使用的 `model_name`）和对应的模型参数 |

`models` 内每个模型的参数（都是 `true` / `false`，可以不写代表默认都不支持）：

| 字段 | 说明 |
|---|---|
| `visual_sense` | 是否支持输入视觉/图像 |
| `audio_sense` | 是否支持输入音频/语音 |
| `video_sense` | 是否支持输入视频 |
| `document_sense` | 是否支持输入复杂文档（如 PDF 解析） |

配置号池的例子：

```json
"api_key": [
    "AIzaSy???????????????????????????",
    "AIzaSy???????????????????????????",
    "AIzaSy???????????????????????????"
]
```
